Reviewer guide

DNS64 Browser Extension 1.4.4 · how to set up a test server and verify every feature · ~10 minutes

Short version. The extension has no backend and no account system. It is a remote control for the DNS64 blocklists of a Node64 instance the user runs themselves. Without such an instance the popup shows its setup form – that is the expected state, nothing is broken.

1. Run a Node64 instance

Node64 is an open-source DNS server for home networks (Apache-2.0, amd64 and arm64). One container is enough; no account, no credentials, no paid tier:

docker run -d --name node64 -p 8080:8080 -v node64-data:/data ghcr.io/ipv64net/node64:latest

The image is also on Docker Hub as x64gmbh/node64. The web UI answers on http://localhost:8080; the first-run assistant asks for a language and an admin account – pick any password you like, there is no default one.

2. Enable the DNS64 module

Do not skip this step. DNS64 is a module inside Node64 and ships switched off. While it is off, nothing runs and the extension's API calls return 404 – the popup would show “DNS64-Modul aus” instead of data.
  1. In Node64 open Settings → Modules and switch DNS64 on.
  2. Nothing else is required: the module starts with its default blocklists and default upstreams, and the overview under DNS64 → Overview shows the running service.
  3. Optional, only to produce traffic: point a test device (or your OS resolver) at the container's IP on port 53 and browse a few sites – then the query log and the counters have data.

3. Create an API key

In Node64 open Settings → API keys, create a key (any name, e.g. “review”). It is shown once and starts with node64_. The key belongs to the node, not to the extension.

4. Set up the extension

  1. Click the extension icon. The popup shows a setup form with both fields empty.
  2. Node address: http://localhost:8080 · API key: the key from step 3.
  3. Press Speichern und testen. Expected message: “Verbunden mit DNS64 <version>”, then the popup switches to the main view.

5. What to verify

FeatureHow to test / expected
Main view Blocking state, counters for the last 24 h (queries, blocked, clients, ratio), footer with DNS64 and extension version.
Pause / resume The switch at the top pauses blocking until you re-enable it; the buttons 1m 5m 30m 1h ∞ and … (custom 1–1440 min) pause for that period and the popup shows a live countdown. The state is written to the local node.
Domain card Open any site (e.g. https://example.com) and click the icon: it shows that domain's status. Erlauben adds it to the node's allowlist, Sperren to its own blocklist; pressing again removes it. Both are visible in the node UI under DNS64 → Allowlist / Own blocklist.
Toolbar badge ON green while blocking is active, OFF amber while paused, ! red when the node is unreachable or the key is wrong (docker stop node64 reproduces it).
Options page Gear icon → same address and key, theme setting, connection test. Theme follows the browser's light/dark mode.
Permissions in use storage (settings), alarms (badge refresh every minute), activeTab (hostname of the active tab, only after a click) and host access to the address entered in step 4.

6. What the extension does not do

  • No remote code. Everything is in the package: no eval, no script tags to external files, no dynamically loaded modules.
  • No content scripts, no page reading. The manifest contains no content_scripts and no scripting permission; only the active tab's hostname is read, after a click on the icon.
  • No third-party servers. Every request goes to the address entered in step 4, and only to these endpoints: /api/dns64/status, /summary, /log, /allowlist, /denylist, /records, /pause, /resume. DevTools → Network shows nothing else.
  • No telemetry, no analytics, no accounts, no ads. The API key stays in chrome.storage.local and is never synced.

7. Notes

  • The UI language is German; the store listing says so. Buttons: Erlauben = allow, Sperren = block, Speichern und testen = save and test.
  • Developer shortcut for the domain card without browsing: popup.html?site=example.com.
  • Pauses and allow/deny entries apply node-wide, not per device.
